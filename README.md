## 项目简介

这是一个**从零开始、逐步迭代构建**的人脸识别考勤系统。项目最大的特色是完整记录了 **12 个原型迭代**（P1 → P12）的开发过程——每个阶段只解决一个具体问题，验证一项关键技术，最终集成为完整的桌面应用。

这种"分而治之、逐步集成"的开发方式，确保了每一步都经过验证，降低了最终集成的风险。

### 核心功能

- **人脸打卡**：摄像头实时人脸追踪 → 百度AI人脸搜索 → 自动记录上下班时间
- **人脸注册**：摄像头采集人脸 → 质量检测 → 注册到百度AI人脸库 + 本地数据库
- **人脸删除**：从云端人脸库和本地数据库同步删除用户信息
- **考勤查询**：表格展示打卡记录（工号、姓名、上班时间、是否迟到、下班时间、工作时长）
- **迟到判定**：自动判断上班打卡时间是否晚于 8:00
- **工时计算**：下班打卡时自动计算当日工作时长

## 技术栈

| 分类 | 技术 | 说明 |
|------|------|------|
| GUI框架 | wxPython 4.x | 跨平台桌面应用框架，Notebook多标签页 |

| 并发处理 | _thread | 子线程执行摄像头操作，避免GUI阻塞 |

## 12步迭代演进

本项目最大的特色是**完整的迭代开发过程**。以下是每个阶段的目标和产出：

### 第一阶段：GUI基础搭建（P1 → P3）

| 迭代 | 目标 | 产出 | 关键技术点 |
|------|------|------|-----------|
| **P1** | 验证GUI框架 | 一个带文本框和按钮的空窗口 | wxPython基础组件、事件绑定 |
| **P2** | 设计完整UI布局 | 4个Tab页的完整界面骨架 | wx.Notebook多标签、背景图片、布局管理 |
| **P3** | 状态管理重构 | 分离UI和数据初始化 | init_data() / initMenu() 职责分离 |

**设计决策**：先搭UI骨架再填充逻辑，确保界面交互合理后再开发后端功能。

### 第二阶段：百度AI API验证（P4 → P9）

| 迭代 | 目标 | 产出 | 关键技术点 |
|------|------|------|-----------|
| **P4** | 获取API访问令牌 | access_tokens() 函数 | OAuth 2.0 client_credentials 模式 |
| **P5** | 人脸注册 | 单张图片注册到人脸库 | BASE64编码、/face/v3/faceset/user/add |
| **P6** | 人脸更新 | 更新已注册用户的 face | /face/v3/faceset/user/update |
| **P7** | 人脸删除 | 两步删除（获取token → 删除） | /face/v3/faceset/face/getlist + face/delete |
| **P8** | 用户查询 | 查询用户注册信息 | /face/v3/faceset/user/get |
| **P9** | 列表查询 | 获取组内所有用户/人脸列表 | /face/v3/faceset/group/getusers |

**设计决策**：每个API单独验证，确保网络连通性、参数格式、错误处理都正确后再集成。

### 第三阶段：核心能力验证（P10 → P11）

| 迭代 | 目标 | 产出 | 关键技术点 |
|------|------|------|-----------|
| **P10** | 人脸识别 | 人脸搜索匹配 | /face/v3/search、相似度阈值（≥80分） |
| **P11** | 数据库操作 | 考勤表CRUD | SQLite建表、游标操作、数据持久化 |

**数据库表设计**：
```sql
CREATE TABLE attendance (
    user_id       CHAR(50) PRIMARY KEY NOT NULL,  -- 工号（主键）
    user_name     CHAR(50) NOT NULL,              -- 姓名
    sign_in_time  DATETIME,                       -- 上班打卡时间
    checking_state CHAR(10) NOT NULL,             -- 打卡状态（是否迟到）
    sign_out_time DATETIME,                       -- 下班打卡时间
    working_time  FLOAT                           -- 工作时长（小时）
);
```

### 第四阶段：完整集成（P12）

将所有验证通过的功能模块集成为完整应用：

```
P1-P3 (GUI)  +  P4-P9 (API)  +  P10 (识别)  +  P11 (数据库)
     ↓               ↓               ↓               ↓
     └───────────────┴───────────────┴───────────────┘
                             ↓
                    P12: 人脸识别考勤系统
```

**集成要点**：
- OpenCV Haar级联检测 → 自动定位人脸区域
- 人脸质量检测（score ≥ 0.8）→ 过滤模糊/侧脸
- 多线程（_thread）→ 避免摄像头操作阻塞GUI
- 上下班自动判断 → 首次打卡为上班，再次打卡为下班
- 迟到自动判定 → 8:00后打卡标记为迟到
- 工时自动计算 → 下班时间 - 上班时间

## 快速开始

### 环境要求

- Python 3.8+
- 摄像头（笔记本内置或USB摄像头）
- 百度AI云账号（人脸识别API）

### 安装步骤

```bash
# 1. 克隆仓库
git clone https://github.com/RuiQiong1/PunchCard.git
cd PunchCard

# 2. 安装依赖
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 3. 配置百度AI密钥（二选一）
# 方式一：设置环境变量（推荐）
# Windows:
set BAIDU_FACE_AK=你的AK
set BAIDU_FACE_SK=你的SK
# Linux/Mac:
export BAIDU_FACE_AK=你的AK
export BAIDU_FACE_SK=你的SK

# 4. 启动应用
python main.py
```

### 获取百度AI密钥

1. 访问 [百度AI开放平台](https://ai.baidu.com/)
2. 创建"人脸识别"应用
3. 获取 API Key (AK) 和 Secret Key (SK)

## 使用流程

### 1. 人脸注册

1. 切换到"人脸注册"标签页
2. 输入工号和姓名
3. 点击"注册"按钮
4. 面对摄像头，系统自动采集人脸
5. 通过质量检测后，注册到百度AI云 + 本地数据库

### 2. 人脸打卡

1. 切换到"员工打卡"标签页
2. 点击"打卡"按钮
3. 面对摄像头，系统自动识别
4. 识别成功（相似度≥80）后自动记录打卡时间
5. 首次打卡=上班，再次打卡=下班，自动计算工时

### 3. 考勤查询

1. 切换到"信息查询"标签页
2. 点击"查询"按钮
3. 表格展示所有员工的打卡记录

## 面试要点

### 30秒电梯演讲

> 这是一个从零迭代构建的人脸识别考勤系统。我用12个原型逐步验证了GUI框架、百度AI人脸API、OpenCV摄像头控制、SQLite数据存储等关键技术，最终集成为一个完整的桌面应用。系统支持人脸注册、打卡识别、迟到判定、工时计算等功能。

### 技术亮点

**1. 为什么用迭代式开发？**
- 每个技术点独立验证，降低集成风险
- 快速暴露API兼容性问题（如百度AI的BASE64格式要求）
- 便于回溯和复现每一步的实现

**2. 为什么用Haar级联而不是深度学习检测？**
- 资源受限场景（本地CPU）下Haar更快
- 百度AI已提供高质量的人脸识别，本地只需做粗定位
- Haar检测 + 云端识别的组合，平衡了速度和精度

**3. 为什么用多线程？**
- wxPython的MainLoop是单线程的
- 摄像头读取是阻塞操作，会冻结GUI
- 用_thread启动子线程，通过标志变量控制状态

**4. 人脸质量检测的作用？**
- 模糊/侧脸会导致低分匹配，产生误识别
- 质量检测阈值（0.8）过滤低质量图像
- 3秒间隔防止重复检测，降低API调用频率

### 常见问题

| 问题 | 回答要点 |
|------|----------|
| 识别准确率如何？ | 百度AI返回相似度分数，阈值设为80分，注册时要求正脸 |
| 如何处理多人同时入镜？ | Haar检测取最大人脸区域，暂不支持多人同时打卡 |
| 数据如何同步？ | 本地SQLite + 百度AI云双写，删除时先删云端再删本地 |
| 离线能用吗？ | 不能，人脸识别依赖百度AI云API，本地只存考勤记录 |
| 如何改进？ | 本地人脸检测换为MTCNN/RetinaFace，支持多人同时检测 |

## 改进方向

- **本地人脸识别**：集成 dlib / face_recognition 库，支持离线识别
- **多人同时检测**：使用 MTCNN / RetinaFace 替代 Haar 级联
- **活体检测**：增加眨眼/张嘴等动作验证，防止照片欺骗
- **Web版本**：用 Flask + WebRTC 实现浏览器端人脸识别
- **数据导出**：支持考勤记录导出为 Excel / CSV
- **消息通知**：迟到时自动发送钉钉/微信通知
